# 架构说明

## 职责分配

LaunchApp 仍作为独立 MatrixOS 应用运行在 Mystrix 上。设备转发原始按键变化，并显示电脑发来的 RGB 灯光。Ableton Live 和 Remote Script 负责 Fn 手势、Live 操作、状态识别、RGB 渲染和动画相位。

    Mystrix App  -- 原始按键事件 --> Live Remote Script 与 Live API
    Mystrix 灯光 <-- 已确认的 RGB 灯光帧 -- 电脑端渲染器

## 组件

- 设备启动入口：启动应用，并把导入步骤控制在 MicroPython 可用内存范围内。
- 设备协议和输入模块：编码按键事件、会话身份、确认信息和受限 SysEx 消息。
- 设备灯光接收器：暂存并验证电脑发来的颜色/映射更新，完整通过后再应用。
- Live Remote Script：读取 Live 状态、沿用 V1 操作逻辑、处理手势与导航、渲染网格并发送变化。
- 电脑端帧发送器：限制待发数据、跟踪确认状态，并在错误后重新同步。

## 协议 v11

V2 两端都使用 SysEx 协议 v11。电脑分配的会话编号可阻止旧连接中的按键或灯光消息生效。设备输入事件携带序号和时间戳；灯光帧会收到确认。最多 16 个变化颜色槽可放入受限差异包；较大的更新分块暂存并原子提交。无效或不完整的更新不会覆盖最后一张有效画面。

RGB 颜色由电脑计算。Mystrix 只保存受限的 RGB 颜色表和格子映射，不解释 Live 概念、速度或动画状态。

## Live 与时序

Live 是 Track、Clip、Scene、速度、走带以及启动/停止队列的唯一状态来源。V2 沿用 Live 脚本中的 V1 操作和安全规则。电脑端请求 Live 自带定时器每 10 毫秒服务一次，并以 40 毫秒画面刷新和初始 SysEx 包间隔为目标。这些都是目标值；实际调度与灯光时序取决于 Live、电脑、USB MIDI 和设备固件。

## 兼容边界

V1 协议 v7 与 V2 协议 v11 必须各自成套。本项目不包含或修改 MatrixOS 固件，也不使用 Developer App 流程；用户从设备上的独立 Launch 应用启动。
